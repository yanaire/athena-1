# Writing a manuscript in Athena

Open a project conversation and enable offline analysis in its execution settings. In Research → Manuscript, add UTF-8 material or a published data result, then select the sources, title and objective. Generate an outline, or enter one to eight headings. Save edits to the outline before starting **Write and review**. Each start is an explicit Pi request using the conversation's pinned model. Cancel stops the existing run. Opening a project after a restart lists saved manuscripts and partial work without starting a new request.

When a research coordinator supplies `librarySources`, each citation includes the saved source ID, edition and its intended use. The host verifies the edition in the current project's library and grants its frozen text to the manuscript workers. Approved citations appear in the compiled references and evidence export.

If the independent reviewer still requests changes after the automatic revision, open **Manuscript preview** and select **Revise from review**. The editor receives the exact previous manuscript and review findings. A fresh reviewer checks the revised edition against its frozen sources. The original research run keeps its model settings and experimental results. Expand **Research activity** in the chat to inspect the recorded work.

For an approved PDF made with an older renderer, **Update typesetting** compiles the same reviewed text with the current renderer. The previous PDF remains downloadable during compilation.

The coordinator can supply a section plan with each heading’s purpose, numbered sources and proposed visual. When the selected evidence includes a bibliographic record, the host requests this plan from a worker if the coordinator omitted it. It resolves the source numbers to immutable project editions and saves the briefs with the manuscript run. The writer returns a structured draft for each heading. The editor calls a host publication tool which executes the bundled offline QuickJS through the existing process queue. Its actual Markdown and JSON evidence map must pass normal artifact verification. A fresh child receives the frozen sources and both artifacts, reads them through the granted file tools, and submits claims, citations and figure-data checks through ResearchLedger. The host records evidence quotes, offsets and source versions. Figure links include the data artifact, variable, unit, transformation and caption. Textual checks and independent reviewer judgments cannot establish visual correctness or reproduce an experiment.

A changes-required verdict permits at most one further editor turn, using the same editor and a new reviewer. Writing, editing and the first review require three direct children. With five or more available child slots, a dedicated session plans the literature coverage. At a lower limit the writer plans coverage in its own session. A second review requires one remaining child slot. Model slots are released while waiting. Source, artifact, queue and job limits still apply. A manuscript run has no separate global price, token or wall-clock budget. The chat sidebar shows the writer’s public section text as it arrives and the editor’s proposed manuscript during publication. Athena checkpoints the working draft in SQLite and displays the approved revision and PDF when available. A chat-led research project can resume its saved workflow checkpoint after an interruption.

The host issues source IDs, SHA-256 digests and immutable document versions. The document service uses project/document IDs and checks expectedCurrentVersion inside a SQLite transaction. Manual edits always create an unreviewed version. The export controls download the selected Markdown bytes and a JSON manifest with source contents, digests, links, original artifact identity, review and unresolved findings. An explicit export has its own stored bytes and hash. These download records do not impersonate execution receipts. Chat-led research projects also expose the exact reviewed TeX and PDF in Manuscript preview.

## Compiling a reviewed revision

The host runs `pdflatex` with shell escape disabled in a private temporary directory. Install a TeX distribution with the selected class and packages. Install Poppler's `pdftoppm` for the in-app page previews (up to 16 pages). The PDF download contains all compiled pages. Compile failures preserve the engine message on the selected revision. Use **Typeset reviewed revision** after restoring the dependency.

Choose `article`, `elsarticle-3p`, `IEEEtran` or `acmart`, or attach a UTF-8 `.tex` file and name it in the request. Attached templates contribute their supported document class, options and packages. The host fills the body with the approved manuscript. Unsupported preamble commands and unstaged figures produce an error. The TeX export contains the generated tables and plots and can be compiled with the same TeX installation.

For recorded numeric arrays, the editor can include `![Caption](athena-plot:sourceId/xKey/yKey)` or `![Caption](athena-table:sourceId/xKey/yKey)` on a separate line. The host resolves the frozen source version and reads the indicated numeric fields directly from its JSON path. A plot shows each measured point in data coordinates. Both forms accept up to 256 conditions. A method diagram can use `![Caption](athena-diagram:sourceId/First%20label/Second%20label)`. Two to six labels must occur in sequence in the linked full-text edition. The compiler escapes the labels and draws the sequence in TeX.

## Finding bibliography candidates

Under **Manuscript → New manuscript and sources → Search Crossref**, enter a query or an exact DOI. **Search** runs it immediately. **Authorize for chat** creates a single conversation-scoped search ID. Give that ID to the current coordinator to execute the same search through the Pi tool. Payment credentials, attachments and manuscript text are never added to the request. The host records the actual tool invocation, attempt, task and run for chat searches. Review a candidate and choose **Add source** to make its exact edition selectable in the manuscript.

The provider interface retrieves bounded pages for a fixed search specification and reports completed pages with their retrieval time. The public Crossref adapter uses one active request, five records per page, up to two query pages or one DOI lookup, no automatic retry, a 20-second total deadline and a 512 KB response cap. It paces queries at one per second and DOI requests at five per second, slowing for stricter response headers and Retry-After. A concurrent request returns busy. The host retains up to 128 searches per project. Successful exact queries can be served from the project cache for ten minutes. The UI identifies cache hits, original retrieval time, empty successes, partial pages, cancellation and provider failures. Restart preserves completed pages and marks unfinished searches interrupted. [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) · [Public access limits](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/)

Records include the normalized DOI, original returned metadata object and its serialized SHA-256, query, retrieval time, source content SHA-256 and exact version. The manifest keeps author and publication fields as returned, abstract availability, full-text URLs and acquisition status. Metadata or abstract coverage depends on what was received. Adding a search candidate preserves its retrieved coverage. The project library’s archive operation can also retrieve a supported open publication and record the original file, digest, and extracted coverage in the project folder. Duplicate DOIs within a search are collapsed. Adding the same edition twice returns the same project source. A changed metadata edition gets a separate immutable source, preserving citations to the earlier edition.
